Performance update - 2026-10-02
Single flame calculator

Changed probability_at_least() to use the aggregated score-distribution
algorithm instead of enumerating every possible flame outcome.
No new caching was added. Threshold calculations use unrounded scores to
preserve fractional-score comparisons; the bulk planner's default rounding
behavior remains unchanged.

Local benchmark:
- Level 150 armor, boss equipment, Black Flame, STR main stat,
  default score weights, target score 120.
- Previous outcome enumeration: 5.3214 seconds.
- New uncached score distribution: approximately 0.0030 seconds.
- Measured speedup: approximately 1,745 times faster.
- Probability difference: 0.
- This is one local calculation benchmark, not end-to-end API latency;
  timings will vary by configuration and environment.

Validation:
- Flame regression tests passed, including fractional thresholds and
  weapon calculations.
- Added comparisons against outcome enumeration for all three flame types,
  boss and non-boss equipment, armor and weapons, and score boundaries.
- The initial broader 40-test run without failures.

Implementation: backend/calc/maplestory_flames.py
Regression tests: backend/tests/test_flames.py

Cleanup and performance update - 2026-10-05
Equipment selection, navigation, CSS organization, and regression tests

Changes:
1. Indexed the static equipment catalog by slot and class families by job.
   Equipment lookups now filter the relevant slot instead of scanning the
   whole catalog and rebuilding class-family mappings on every call.
2. Memoized equipment picker choices by selected slot and class so unrelated
   component renders do not repeat filtering, configuration, and sorting.
3. Extracted navigation actions into navigateToPage(), used by usePageRoute.
   Clicking the current page with a trailing slash no longer adds a duplicate
   history entry. Unknown page keys are ignored before preventing the click.
   Modified clicks, download links, and links targeting another browsing
   context retain normal browser handling.
4. Moved navigation styles from App.css to components/Navigation.css and
   equipment-editor styles from EquipmentWindow.css to EquipmentAnalysis.css.
   Each component imports its stylesheet. Moved rules were kept unchanged.
5. Removed the unused .equipment-class-selector CSS rule.
6. Added regression tests for navigation history and scrolling, duplicate
   routes, invalid routes, new-tab/download behavior, sorted equipment
   choices, repeated lookup isolation, and unknown slots/classes.
   Existing tests continue to cover equipment eligibility, import/export,
   upgrade ordering, probability helpers, and backend calculations/API behavior.
7. Added npm test for the frontend and updated README verification instructions.
8. Updated Demon Avenger's class configuration to have no secondary stat.
   Existing UI conditions hide Secondary stat per main stat in Flames and
   Equipment, and calculation requests no longer include STR as a secondary.

Local equipment lookup benchmark:
- Compared the previous committed implementation with the indexed lookup.
- Verified identical results for all 1,175 supported job/slot combinations,
  including repeated equipment slots.
- Timed 15 passes over these combinations after warming both implementations.
- Previous implementation: 103 ms; indexed implementation: 29 ms.
- Approximately 3.55 times faster, or 72% less time in this measured run.
- This measures equipmentChoices() calls, not browser rendering or API latency.
  Timings vary by environment; the memoized-render benefit was not benchmarked.

Validation:

- All 89 backend tests passed; backend calculation code was unchanged.
- Frontend lint, production build, and git diff --check passed.

Star Force replacement costs - 2026-10-05

- Added replacement cost per boom to the standalone calculator and equipment
  details. Default is 0; Astra secondaries default to 1,000,000,000 mesos.
  Explicit zero/custom values override the default and survive saves/exports.
- Older equipment saves without the field receive the appropriate default.
- Expected total cost now includes expected booms times replacement cost,
  including booms incurred during recovery. Attempts and their percentiles
  are unchanged. The API also returns expected replacement spending separately.
- Equipment upgrade rows display expected booms; grouped ranges sum booms,
  replacement spending, and total costs. Efficiency uses the full total cost.
- Added the optional --replacement-cost-mesos command-line argument.
- Added regression coverage for defaults, overrides, import validation,
  boom-free upgrades, recovery costs, grouped rows, and ranking behavior.
- Validation: 56 frontend tests and 92 backend tests passed; frontend lint
  and production build passed. No new performance benchmark was performed.
